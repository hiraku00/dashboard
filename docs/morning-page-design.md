# モーニングページ（/morning-page）

Obsidian の「朝の書き物」（モーニングページ。2023年6月から毎日）を、日報とは別に、1ページ1行で D1 に持ち、画面で読む。

## なぜ日報の振り返りタブとは別か

日報の6節目「予定と振り返り」（[画面設計 §4.7](daily-report-view-design.md#47-振り返りタブ第5版)）は、**日報（画面ログ）のある日にだけ**付く。日報の最古は 2025-12-23 で、それ以前のモーニングページ（約885ページ）には付ける先が無い。そこで、日報と独立した入れ物を作る。日報のある日の予定と実績は、今までどおり日報の「振り返り」タブで読み、この画面からそこへ案内する。

## データ

`morning_pages`（1ページ1行。`migrations/0024_morning_pages.sql`、schema version 23）。**本文は置かない。**

| 列 | 内容 |
| --- | --- |
| `page_date` | 主キー。ページの日付 |
| `started_at` / `ended_at` / `minutes` | ヘッダーの表「時間」から。4時間を超える所要時間は書き間違いとして `NULL` |
| `place` | ヘッダーの表「場所」 |
| `chars` | 本文の文字数（空白とURLだけの行を除く）。ヘッダーの「文字数」は3割のページにしか無いので、本文から数える |
| `yesterday` / `plan` / `notes` | そのページに書かれた「昨日のこと」「今日の予定」「気になったこと」（JSON の文字列配列、各400字・16件まで） |
| `extracted` | 上の3つを Claude で取り出したか。日報のある期間（2025-12-23 以降）は `0`（ヘッダーだけ） |
| `content_hash` | 同じ内容の再送を `skipped` にするための、内容のハッシュ |

## 取り込み

auto-daily-report の `morning_pages.py` が `POST /api/morning-pages`（service token のみ。1リクエスト50件まで）へ送る。`app/lib/morning-page-input.ts` が1件ずつ検証し（不正な件はその件の `error`）、`app/lib/morning-page-store.ts` が既存のハッシュと比べて、変わった・新しいページだけを1回の `DB.batch` で書く。何度送り直してもよい。

## 画面

月を単位にする（データのある月だけ押せる。年ごとのチップと前後の月）。`?month=YYYY-MM&tab=overview|days|notes&q=`。D1 は1回の `batch`（月ごとの集計・開く月の行・検索）で読む。

- **概要**: 書いた日（N/月の日数）・平均の所要時間・平均の文字数、日ごとの所要時間の棒（書かなかった日は点）、場所（かっこの前でまとめる）、月ごとの推移
- **日ごと**: 書いた日を1日ずつ開閉。開くと「昨日のこと・今日の予定・気になったこと」。日報のある期間の日は、日報の振り返りタブへのリンク
- **気がかり**: その月の気がかりの一覧。検索語があれば、全期間の昨日のこと・予定・気がかりから検索（新しい日から最大60ページ）。D1 の LIKE は50バイトまでなので、検索語は切り詰める

## 限界

- 「昨日のこと」は、そのページに書かれた分だけ。前日の出来事を書かない日（2023年に多い）は空になる
- 予定の達成（済・未）は出さない。結果の根拠（日報）が無いため
- 取り出しは Claude が書くので、人名・店名・時刻に誤りがありうる
