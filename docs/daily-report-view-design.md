# 作業日報（auto-daily-report）の表示設計 — 第4版

[取り込み設計](daily-report-ingest-design.md)でD1に入れた日報を表示する画面の設計。第3版（#253）で概要は整理できたが、**概要以外のタブ（時間の使い方・作業内容・知見・メモ・原本）は第2版のまま**だった。第4版では、デジタル庁デザインシステム（DADS）の基準とノンデザイナーズ・デザインブックの4原則で、全タブを同じ作法に揃える。タブ・ツールバー・カレンダー・URL・D1の読み取りは変えない。

## 0. 第3版の問題と、第4版での直し方

| 指摘 | 原因（確認した事実） | 第4版での直し方 |
| --- | --- | --- |
| 概要がシンプルになったので、活動時間の棒はカテゴリで色分けしてよい | 第3版は「色はカテゴリの意味だけに使う」ため1色にしていた。いまは概要の要素が少なく、配分の表が隣で凡例を兼ねる | 活動時間の棒を**カテゴリの積み上げ**に戻す。区間の間に白い隙間（1.5px）を入れ、色は §5 の新しい4色。配分の表と同じ色・同じ順で、表が凡例を兼ねる（1列のスマホでは図の下に凡例を1行） |
| 時間の使い方がごちゃついている | 7行の帯が4色＋斜線の短い区間で埋まり、その下の時刻別の平均も4色の積み上げ。さらに上に凡例の帯。1画面に色の区間が数百ある | **既定は1色**（活動=濃い灰青、ログなし=斜線）で「いつ活動したか」だけを見せる。帯の上の切り替え（`すべて｜学習｜開発｜生活｜視聴`）でカテゴリを1つ選ぶと、そのカテゴリだけ色を付け、ほかは薄い灰にする（強調は1色＋灰）。時刻別の平均も同じ切り替えに従う1色の棒にし、帯と同じ横軸で**同じパネルの真下**に置く（整列・近接）。縦軸（0・30・60分）を付ける。凡例の帯は切り替えが兼ねるので削除 |
| 作業内容をもっとまとめるべき | 見出し（`###`）の単位で並べていたが、見出しはLLMが毎日違う言い方で書く（「電気工事士の学習」「電気工事士の学習・動画視聴」「電気工事士・動画視聴」）。1週間で十数行になり、まとまらない | **タグの単位**にまとめる（「電子工作・電気」「英語学習」…）。表の列は `タグ`・`時間`（合計）・`日数`・`最新の内容`（1行）。カテゴリごとに小計の行を置く。行を開くと、そのタグの作業項目を日付順に全部出す。時間はタグ×日の分数（取り込み時に計算済み）なので、作業内容と時間が同じ表で読める |
| アプリを日ごとに塗ったり、日数・回数を書いても意味がない。時間ではないのか | 日報のアプリ表にあるのは「使用回数」（画面キャプチャに写った回数の概数。「340+」「546（記録上のアプリ名）」など）だけで、**アプリ別の時間は日報に無い**。しかも1回のキャプチャに複数のアプリが数えられるので、回数から時間は割り出せない | 週次・月次のアプリの図は**削除**する。アプリの表は日報の原文の一部として「原本」タブで読める。アプリ別の時間が要るなら、日報の生成側（auto-daily-report）で時間を出してもらう必要がある（§10） |
| 知見・メモをもっと表らしく | 日付ごとの箇条書きを縦に並べていた | DADS のテーブル（Dense 16px）にする。列は `日付`・`知見`・`カテゴリ`。カテゴリは知見の文にタグ辞書（`tagsForText`）を当てて表示時に決める（D1は変えない）。表の上に**検索欄**と**カテゴリの切り替え**を置き、その場で絞り込む |
| 全体にUI/UXを改善。デジタル庁のように | 文字が11〜12pxの箇所が多い（凡例・注記・軸・チップ）。DADS は本文16px、補足でも14px以上で、**14px未満は原則として使わない**。グラフの色（琥珀・緑青・桃）は地とのコントラストが3:1未満で、DADS の「文字以外の要素は3:1以上」を満たさない | §11 の文字の規則（本文16px、表は14〜16pxのDense、最小14px、行間1.5以上、リンクは下線）を全タブに当てる。グラフの4色を、3:1以上で全ペア見分けられる色に替える（§5） |

**第4版の後の調整（本番で見た指摘）**

- 概要: 2枚のパネルの高さを揃える（左の活動時間の図を、右の配分の表の高さまで伸ばして描く）。
- 時間帯タブ: 既定（すべて）でもカテゴリの色で表示する（帯も時刻別の平均も4色）。1つ選ぶとそのカテゴリだけ色を残し、ほかは薄い灰。§4.3・§5.3 の「既定は1色」はこれで置き換える。
- タブ名を2文字に揃える: `概要・時間帯・作業・知見・原本`（第4版までは `概要・時間の使い方・作業内容・知見・メモ・原本`）。

DADS のどの規則を採ったかは §11 にまとめる。色・フォントのトークン（地の色、アクセントの青、フォント）はポータル共通のまま（日報だけ DADS のトークンにすると、ほかの画面と不揃いになる）。採るのは文字の大きさ・行間・コントラスト・表の作法。

## 2. 方向宣言

- ジョブ: 好きな日・週・月をすぐ開き、「何に何時間使ったか」「いつやったか」「何をしたか」「何を学んだか」を、切り口ごとのタブで読む。
- レジスター: 主=精密、副=親愛。Manage Asset と同じ「数値と構造を優先する落ち着いた道具」。欠落や視聴の多さを責めない。
- サーフェス: web。**Manage Asset と同じワークスペース**（ヘッダー直下のタブ、ヒーロー、パネル）。
- パレット: 地・面・文字・アクセントはポータルの既存トークン（`--bg` `--surface` `--ink` `--blue`）。データの色は§5の4色＋灰。
- タイポ: 既存の日本語サンセリフ、数値は `tabular-nums`。ヒーローの主数値だけ大きく（Manage Asset の `asset-hero strong` と同じ28px）。
- 余白リズム: 8pxグリッド。Manage Asset と同じパネル間16px。
- モーション: 160ms ease-out。タブ・期間の切り替えと、帯⇔表のハイライトだけ。
- シグネチャー: どのタブにいても、ツールバーの「日次／週次／月次」と日付はそのまま残り、タブを替えても見ている期間が変わらない。
- 禁じ手: 1つのページに全部を縦積みすること、凡例の無い色、彩度違いで色数を増やすこと、円グラフ、増減の緑・赤、日付の移動手段を矢印だけにすること。

## 3. 画面の骨格（ヘッダー → タブ → ツールバー → 本文）

```text
┌ 作業日報                                                   ログアウト ┐
│ ホーム  Watch List  ちきりんオプチャ  TextTube  Manage Asset  To Do  日報  使用量 │
│ ───────────────────────────────────────────────────────────── │
│ 概要   時間の使い方   作業内容   知見・メモ   原本              ← 機能内タブ(asset-tabs) │
└───────────────────────────────────────────────────────────── ┘
┌ ツールバー(page-toolbar) ──────────────────────────────────────┐
│ [週次 ▾]   ‹  [📅 2026/10/19(月)〜10/25(日) ▾]  ›   今週へ              │
└──────────────────────────────────────────────────────────────┘
  ↓ 日付ボタンを押すとカレンダー(ポップオーバー)
  ┌ ‹ 2026年10月 › ────────────┐
  │ 月 火 水 木 金 土 日          │   ● = 日報あり(押せる)
  │          ●1 ●2 ●3 ●4         │   ・ = 日報なし(押せない、薄く)
  │ ●5 ●6 ・7 …                   │   週次は押した日を含む週の行ごと選ぶ
  └──────────────────────────┘   月次は12か月の格子(日報のある月だけ押せる)
```

### 3.1 期間の単位（プルダウン）

- `日次`・`週次`（月曜始まり）・`月次`（暦月）の `<select>`。Manage Asset の期間セレクターは選択肢が4つの `period-control`（ボタン群）だが、ここは**単位**の切り替えで、日付の表示とセットで読むものなので、ユーザーの指定どおりプルダウンにする。
- 単位を替えたときの日付: 日次→週次はその日を含む週、週次→月次はその週の月曜の月、上位→日次はその期間の**最後の日報のある日**。

### 3.2 前後の移動とカレンダー

- `‹` `›` は**単位ごと**に1つ動く（日次=1日、週次=1週、月次=1か月）。日次は日報のある日へ飛ぶ（無い日を踏まない）。週次・月次は日報が無い期間でも動く（「この週は日報なし」と出す）。
- 日付ボタン＝カレンダーのポップオーバー。日報のある日に印を付け、無い日は押せない。月の送りもポップオーバー内で行う。キーボードでは矢印キーで日付を移動し、Enterで確定、Escで閉じる。
- 「今日へ／今週へ／今月へ」（単位に合わせて文言が変わる）。
- 日報のある日付の一覧は、ページを開くとき `SELECT report_date FROM daily_reports` で一緒に読む（全件で数百行。主キーの索引だけで読める）。カレンダー・前後移動・単位の切り替えはこの一覧から決まるので、追加の問い合わせは要らない。

### 3.3 URLと状態

- `/daily-report?range=week&date=2026-10-19&tab=time`。期間（`range`・`date`）はサーバーで読み直すのでリンクで移動、**タブは手元で切り替え**（Manage Asset と同じく、全タブを描いて `hidden` で隠す。切り替えは即時で、URLは `history.replaceState` で `tab` だけ書き換える）。
- 既存の `/daily-report/2026-10-21` は `/daily-report?range=day&date=2026-10-21` へ転送する（#248のリンクを壊さない）。
- 既定（パラメーター無し）は**週次・今週**。今週に日報が1件も無ければ、最新の日報がある週。

## 4. タブと、単位ごとの中身

| タブ | 日次 | 週次 | 月次 |
| --- | --- | --- | --- |
| **概要** | ヒーロー／左に**1日の帯**（表なし。表は「時間の使い方」）／右に配分の表（比べる相手=直近28日の1日平均）。週次・月次と同じ「左に時間、右に配分」の並び（配分の表だけだと右半分が空いたため、実装時に帯を置いた） | ヒーロー（合計と1日平均）／**活動時間の図**（日ごと7本⇔最近12週）／**配分の表**（4カテゴリ×合計・1日平均・前週の1日平均） | 週次と同じ。活動時間の図は日ごと（日数分）⇔最近12か月 |
| **時間の使い方** | 1日の帯＋時間帯の表（§4.3）。表のカテゴリは1列の文字（タグのチップは出さない） | カテゴリの切り替え＋**7行の帯**＋同じ横軸の**時刻別の平均**（§4.3） | カテゴリの切り替え＋時刻別の平均＋曜日別の平均（§4.3） |
| **作業内容** | タグ単位の表（§4.4。日数の列なし） | タグ単位の表（タグ・時間・日数・最新の内容。行を開くと日付順の作業項目） | 同左 |
| **知見・メモ** | 知見の表（日付の列なし） | 知見の表（日付・知見・カテゴリ）＋検索欄＋カテゴリの切り替え（§4.5） | 同左 |
| **原本** | その日のMarkdown全文＋解析時の警告 | 日報の一覧の表（日付・活動時間・記録・ログなし・解析）。日付は下線付きのリンクでその日の原本へ（§4.6） | 同左 |

- どのタブでも、期間に日報が無ければ「この期間の日報はありません」と、前後で日報のある期間へのリンクを出す。
- 「概要」の活動時間の図（日ごと）・「時間の使い方」の週の帯は、**日次へ降りる入口**を兼ねる（押すと `range=day` に替わり、同じタブのまま）。週ごと・月ごとの棒は、押すとその週次・月次へ。
- 作業内容の「やったこと」は、月次では出てきた日を全部チップにせず「12日・10/1〜10/21」と日数と範囲だけを書く（第2版は日付のチップが行を埋めていた）。週次は曜日のチップのまま。

### 4.1 概要タブの構成（第3版）

```text
┌ ヒーロー(asset-hero) ───────────────────────────────────────────────────┐
│ 合計             1日平均        │ 前週の1日平均      │ ログなし          │ 日報     │
│ 31h40m           10h33m         │ 9h51m              │ 9h12m             │ 3/7日    │
│                                  │ +42m/日            │ 記録の22%         │ 木〜日はまだ│
└──────────────────────────────────────────────────────────────────────┘
┌ 活動時間 ── [日ごと|最近12週] ─────────┐ ┌ 配分 ───────────────────────────┐
│ 12h ┼───────────────────────────── │ │            割合      合計   1日平均  前週 │
│  8h ┼─ ▇ ─ ▇ ─ ▇ ─────────────────── │ │ ● 学習  ████▏ 30%  9h30m  3h10m  2h20m│
```

- 並びは Manage Asset の資産概要（ヒーロー → 左に資産推移・右に資産配分 → 表）に合わせる。PC（1100px以上）は2列（1.35fr : 1fr）、それ未満は1列。
- 概要には凡例の帯を置かない（色が出るのは配分の表だけで、行に名前が付いている）。

**配分の表**
- 行は4カテゴリ＋未分類（0分なら出さない）。列は `割合（細い横棒＋%）`・`合計`・`1日平均`・`前週（前月・直近28日）の1日平均`。数字は右揃え、`tabular-nums`。
- 前の期間との差は、色を付けずに `+42m` `−18m` と1日平均の列の下に小さく書く（第2版の「差を強調しない」を守る）。前の期間の日報が3日未満なら「参考」、0日なら「—」。
- 行を押すと、その下にタグ別の内訳（同じ列）が開く。最初は全部閉じる。日次は `合計` 列を出さない（1日しかないため `時間` 列だけ）。
- 第2版の「今週・前週の2本の100%横棒」と「カテゴリ→全タグの横棒（目盛り付き）」は、この表に置き換えて削除する。

### 4.2 活動時間の図（週次・月次の概要）

- **カテゴリの積み上げ縦棒**（第4版。第3版は1色）。積む順は下から学習・開発・生活・視聴・未分類（配分の表と同じ順）。区間の間に白い隙間1.5px。値は1日の活動時間（日ごと）、または期間の1日平均（週ごと・月ごと）。凡例は隣の配分の表が兼ね、1列になるスマホでは図の下に凡例を1行出す。
- 見出しの右に `period-control`（Manage Asset の資産推移と同じ部品）: 週次は `日ごと｜最近12週`、月次は `日ごと｜最近12か月`。切り替えは手元で行い、URLには残さない（Manage Asset と同じ）。
- 縦軸: 0から始め、最大値を4時間単位で切り上げた上限まで4〜5本の目盛り線（`var(--line)`）。ラベルは左に `4h` `8h` `12h`。
- 棒: 枠の60%の幅（最大28px）、上端だけ角丸4px。隙間は枠の40%。
- 日報の無い日・期間: 棒は描かず、底に幅の短い灰の線と、週ごと・月ごとのときだけ「日報なし」の小さな文字。今日より後の日は何も描かない。
- 横軸のラベル: 日ごと（週次）は曜日、日ごと（月次）は 1・5・10・15・20・25・30 日、週ごとは月曜の日付（`9/28`）を2本おき、月ごとは月（`5月`）。太字は使わない。
- ホバー（タップ）で Manage Asset の `ChartTooltip`: `10/21(水)` / `10h07m` / カテゴリごとに1行。押すとその日（その週・月）へ。
- 軸の文字は14px（§11）。そのため月次の日ごとの日付ラベルは 1・10・20・30 だけにする。
- 第2版の「最近12週（12か月）の流れ」（カテゴリ別の小さな折れ線4枚）は削除する。カテゴリ別の長期の増減は、配分の表の「前週」列と、この図の週ごと・月ごとの切り替えで読む。

### 4.3 時間の使い方タブ（第4版）

```text

│ 月 12  ░░▓▓▓▓▓▓▓▓░░░░▓▓▓▓▓▓▓▓▓▓▓░░░░▓▓▓▓▓▓▓            11h55m     │
│ 火 13      ▓▓▓▓▓▓▓▓▓▓▓░░▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░▓▓▓▓▓▓          11h08m     │
│ …                                                                    │
│ ── 時刻別の平均(分) ──────────────────────────────────────── │
│ 60 ┤          ▆▇      ▅▆▇▇▅         ▆▆                               │
│ 30 ┤      ▂▅▇▇██▅▃▄▅▇██████▅▃▃▅████▂                                 │
│  0 ┴────────────────────────────────────────                         │
│ ▓ 活動  ░ ログなし  ┆ 日報なし                                       │
└──────────────────────────────────────────────────────┘
```

- **1枚のパネルに、帯（7行）と時刻別の平均を同じ横軸で上下に置く**（整列・近接）。第3版は帯と時刻別の平均が別のパネルで、凡例の帯も別にあった。
- パネルの見出しの右に `period-control` で `すべて｜学習｜開発｜生活｜視聴`（各カテゴリは色の四角と期間の割合を添え、凡例を兼ねる）。既定は「すべて」で、帯は活動=濃い灰青の1色。カテゴリを選ぶと、帯はそのカテゴリの区間だけ色、ほかの活動は薄い灰。時刻別の平均も、すべて=活動時間、カテゴリ=そのカテゴリの分数の、1色の棒になる。
- 時刻別の平均には縦軸（0・30・60分）を付ける。高さは帯7行の半分ほど。
- 月次は帯を出さず（31行は読めない）、時刻別の平均と曜日別の平均（7本の横棒、1色、値の文字付き）。
- 日次は、1日の帯（カテゴリの4色。名前付きの凡例を帯の下に1行）と時間帯の表。表の列は `時間帯`・`所要`・`作業内容`・`カテゴリ`（色の四角＋名前を1つ）。第3版のタグのチップ（1行に2〜3個）はやめる。ログなしの行は文字を灰にするだけ（斜線の地はやめる）。

### 4.4 作業内容タブ（第4版）

| タグ | 時間 | 日数 | 最新の内容 |
| --- | --- | --- | --- |
| **■ 学習**（小計） | **31h20m** | | |
| 　▸ 英語学習 | 12h40m | 7日 | Gemini・Ankiで英単語と構文を学習（10/18） |

| **■ 開発**（小計） | … | | |

- 見出し（`###`）ではなく**タグの単位**でまとめる（見出しは日ごとに言い方が変わり、まとまらない）。時間はタグ×日の分数の合計。
- カテゴリの小計の行の下に、タグを時間の多い順に並べる。行を押すと、そのタグの作業項目を `日付`・`内容` の2列で日付の新しい順に全部出す（DADS のディスクロージャーと同じ振る舞い）。

- タグの付かなかった作業項目は「未分類」にまとめる。作業項目と時間帯は日報の別の節から数えているので、作業項目しか無いタグの時間は `—`。

- **アプリの図は出さない**（§0。日報にアプリ別の時間が無い）。アプリの表は原本タブで原文として読める。

### 4.5 知見・メモタブ（第4版）

- 表の上に、検索欄（入力すると知見の文で絞り込む）と `すべて｜学習｜開発｜生活｜視聴｜未分類` の切り替え。件数を「12件中5件」と出す。
- 表の列は `日付`（下線付きのリンク。その日の日次へ）・`知見`・`カテゴリ`。新しい順。同じ日の2件目以降は日付を空にする（同じ日がまとまって見える）。
- カテゴリは、知見の文に `tagsForText()` を当てた最初のタグのカテゴリ。当たらなければ未分類。表示のたびに計算する（純関数で軽い。D1は変えない）。
- 日次は日付の列を出さない。

### 4.6 原本タブ（第4版）

- 日次は第3版のまま（Markdown全文。表・見出しは TextTube の本文と同じスタイル）。
- 週次・月次の日報の一覧の列を `日付`・`活動時間`・`記録`（`08:06〜22:34`）・`ログなし`・`解析` にする。日付は下線付きのリンク。

## 5. 色とカテゴリ

### 5.1 4つのカテゴリ（表示用。タグ辞書は変えない）

| カテゴリ | 色 | 含むタグ（`daily-report-tags.ts` のグループ） | 全期間の割合 |
| --- | --- | --- | --- |
| 学習 | 青 `#2d6fd0` | study（英語、ROS 2、電子工作、CS） | 21% |
| 開発 | 橙 `#b35c00` | dev（dashboard、TextTube、manage-asset、スクレイピング、ジムアプリ、日報ツール、Mulmo、AI、PC、開発その他） | 20% |
| 生活 | 緑 `#16804f` | money＋life（資産・お金、旅行・住まい、買い物、メモ・習慣、連絡・SNS） | 22% |
| 視聴 | 赤紫 `#b5418f` | media（動画・番組視聴） | 36% |
| 未分類 | 灰 `#8a8a8e` | other | 1.5% |
| ログなし | 灰の斜線（色ではなく模様） | — | — |

- 「お金」は単独では3%前後で、帯の上では細い線にしかならないので「生活」に入れる。タグの単位（資産・お金）では引き続き見える。
- カテゴリはD1に保存しない（タグ×日だけを持つ）。表示側の対応表で決めるので、後で分け方を変えても再取り込みは要らない。

### 5.2 色の検証

帯では**どの2色が隣り合うか決まらない**ので、`dataviz` の validator を `--pairs all`（全ペア）で回した。

| 候補 | 通常の色覚での最小差（15以上が必要） | 色覚の差での最小差 | 判定 |
| --- | --- | --- | --- |
| 第1版の5色（青・橙・緑青・黄・桃） | 橙↔桃 12.9 | — | 不合格 |
| 青・橙・緑青・桃 | 橙↔桃 12.9 | 6.1 | 不合格 |
| 青・琥珀・緑青・桃（第2・3版） | 琥珀↔桃 19.6 | 緑青↔桃 6.1（下限帯） | 見分けは合格。ただし琥珀2.11・緑青2.74・桃2.62で、地とのコントラストが3:1未満（DADS の文字以外の要素の基準を満たさない） |
| **青・橙・緑・赤紫（第4版で採用）** `#2d6fd0` `#b35c00` `#16804f` `#b5418f` | 赤紫↔橙 18.7 | 緑↔橙 6.8（下限帯） | 合格。**4色とも地とのコントラスト3:1以上**。下限帯なので、区間の間の隙間と、凡例・表での名前の併記を必ず行う |

未分類は灰 `#8a8a8e`（地とのコントラスト3:1以上）、ログなしは斜線の模様。

### 5.3 色を使う場所と凡例（第4版）

- 色は「カテゴリ」という1つの意味にだけ使う。
- **同時に4色を見せるのは、概要（活動時間の積み上げ・配分の表）と日次の1日の帯だけ**。どちらも隣に名前付きの表か凡例がある。
- 時間の使い方（週次・月次）は**既定が1色**（活動=`#4a5a70` の濃い灰青、ログなし=斜線）。カテゴリの切り替えで1つ選んだときだけ、そのカテゴリの色を付け、ほかは薄い灰 `#d6d8de` にする（強調は1色＋灰。§4.3）。
- 作業内容・知見・原本の表では、色はカテゴリ名の前の小さな四角だけ。文字は常に黒（色だけで区別しない）。
- 彩度・明度を変えて別の意味を持たせることはしない（選択中の強調は枠線で行う）。

## 6. Manage Asset との平仄

### 6.1 使う部品

| 用途 | Manage Asset の部品 | 日報での使い方 |
| --- | --- | --- |
| ワークスペース | `main.portal-shell.asset-workspace` | 同じ |
| 機能内タブ | `PortalHeader` の子に `nav.asset-tabs`（下線のタブ） | 概要／時間の使い方／作業内容／知見・メモ／原本 |
| ツールバー | `page-toolbar` | 単位のプルダウン・前後・日付（カレンダー）・今日へ |
| ヒーロー | `asset-hero` ＋ `hero-grid` ＋ `hero-metric` | 主数値（活動時間）と補助指標 |
| パネル | `asset-panel` ＋ `panel-heading`（見出し＋補足、右に操作） | 各グラフ・表 |
| 期間などの小さな切り替え | `period-control` | 知見のカテゴリ絞り込み、流れの「12週／12か月」など |
| 表 | `asset-table` | 時間帯・アプリ・日報の一覧 |

日報専用に新しく作るのは、データの部品（帯、100%横棒、ブレット、縦棒、カレンダー）と凡例だけにする。第1版の `tube-panel`・独自の見出し・独自の前後リンクは使わない。

### 6.2 ヒーロー（Manage Asset の「総資産・前日保存比・換算レート・最終更新」と同じ並び）

| 単位 | 主（左・大） | 補助1 | 補助2 | 補助3 |
| --- | --- | --- | --- | --- |
| 日次 | 活動時間 `8h17m`（下に `記録 09:17〜22:28`） | 直近28日の1日平均 `9h05m`（`−48m`） | ログなし `4h54m`（`記録の37%`） | キャプチャ `484回` |
| 週次・月次 | **合計 `31h40m` と 1日平均 `10h33m` を同じ大きさで横に並べる** | 前週（前月）の1日平均 `9h51m`（`+42m/日`） | ログなし `9h12m`（`記録の22%`） | 日報 `3/7日`（`木〜日はまだ`） |

補助指標は4つまで（Manage Asset のヒーローと同じ数）。差の `+42m` は色を付けない。

### 6.3 デザインシステムについて

枠組み（タブ・ヒーロー・パネル・ツールバー）は Manage Asset の部品のまま。中身の文字・表・コントラストは、第4版でデジタル庁デザインシステム（DADS）の基準に合わせる（§11）。色とフォントのトークンはポータル共通のままにする（日報だけ変えると、ナビやほかの画面と不揃いになる）。

### 6.4 1日の画面にあった問題の扱い

- 週の帯は「週次」の「時間の使い方」へ移す（日次からは消す）。
- 前後の移動はツールバーに一本化する（ページ内の `‹ 10/17(土)` `10/19(月) ›` は廃止）。

### 6.5 原本のMarkdown

`app/globals.css` の `.texttube-workspace .markdown-body table/th/td/thead/tbody`、`.texttube-workspace .markdown-table-scroll`、`.texttube-workspace .markdown-h3` を、`.markdown-body` 共通（TextTube と日報の両方に効く形）へ移す。TextTube の見た目は変えない（同じ値のまま範囲だけ広げる）。日報の原本は「原本」タブの `asset-panel` の中に置く。

## 11. デジタル庁デザインシステム（DADS）から採る規則（第4版）

[DADS のタイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)と[カラー](https://design.digital.go.jp/dads/foundations/color/)の基準のうち、次を全タブに当てる。

| 規則 | DADS の基準 | 日報での当て方 |
| --- | --- | --- |
| 本文の大きさ | 本文・UIは16pxが基準 | 表の本文・作業内容・知見は16px |
| 最小の大きさ | 14px未満は原則として使わない。14pxは補足や狭い所だけ | 凡例・注記・軸・表の見出しは14px。第3版までの11〜12pxは全てやめる |
| 行間 | 本文は1.5以上（1.7が標準）。データの多い画面は Dense（120〜130%） | 文章（知見・作業の内容）は1.7、表の数値の行は1.3 |
| 表 | 表は表のデータだけに使う。名前と値の組は説明リスト | 作業内容・知見・原本の一覧・配分は表。ヒーローは見出し＋値の組 |
| 文字のコントラスト | 4.5:1以上 | 補足の文字の色が地に対して4.5:1以上かを実装時に確認する |
| 文字以外のコントラスト | 3:1以上（境界線・グラフの要素など） | グラフの4色を3:1以上の色に替える（§5.2） |
| リンク | 下線で示し、色だけに頼らない | 表の中の日付のリンク・「今週へ」などは下線付き |
| 斜体 | 日本語に斜体は使わない | 使わない |

DADS のフォント（Noto Sans JP）と色のトークンは採らない（ポータル共通の設定のまま。§6.3）。DADS の「ダッシュボードデザインの実践ガイドブック」（PDF）は、この環境でPDFを読めなかったため参照していない。

## 7. 統計上の扱い（第1版から変えない点）

- 比べる単位は「日報のある日の1日平均」。合計は補助。
- 差は色で強調しない（1日の活動時間の標準偏差3h07m。5日平均でも標準誤差は約1h24m）。目盛りとのずれで控えめに見せる。比べる相手の日報が3日未満なら目盛りを点線にして「参考」、0日なら出さない。
- ログなしは配分の分母に入れない。
- 複数タグの時間帯は等分（`tagDailyReport()` と同じ）。ツールチップに明記する。
- 円グラフ・ドーナツ・ツリーマップ・レーダーは使わない（比較が主目的、項目が小さい、角度・面積は読み取りが不正確）。

## 8. 読み取り（`app/lib/queries/daily-report.ts`）

1画面＝1回の `env.DB.batch`。期間の単位に関わらず同じ関数 `periodView(range, date)` で読み、タブの中身はすべてそこから作る（タブの切り替えで問い合わせは増えない）。

| 文 | 日次 | 週次 | 月次 |
| --- | --- | --- | --- |
| 日報のある日付の一覧（カレンダー・前後移動） | 全件 約200行 | 同 | 同 |
| `daily_reports`（本文以外） | 1行 | 今期＋前期 14行 | 約60行 |
| `tag_days`（流れ・比較を含む） | 直近28日 約170行 | 12週 約500行 | 12か月 約2,200行（SQLで月×タグに畳む） |
| 時間帯＋タグ | 約10行 | 約65行 | 約280行 |
| 作業項目・タグ・アプリ・知見 | 約30行 | 約200行 | 約800行 |
| 本文（`markdown`） | 1行 | 読まない | 読まない |

合計は日次 約400行、週次 約1,000行、月次 約3,500行。D1の読み取り上限（5M行/日）に対して十分小さい。全期間の集計を毎回読むクエリは置かない。

## 9. 実装の順序

### 9.0 第4版

1. 色の差し替え（§5）と文字の規則（§11）を全タブの CSS に当てる
2. 概要の活動時間をカテゴリの積み上げに（§4.2）

## 10. 採らなかった案

- **アプリ別の時間（第4版）**: 日報にアプリ別の時間が無く、使用回数（キャプチャの概数で、1回に複数のアプリが数えられる）から時間は出せない。必要なら auto-daily-report 側で時間を出力する変更が先に要る。
- **時間の使い方の帯を常に4色（第2・3版）**: 1週間で数百の短い色の区間になり読めない。既定は1色にし、カテゴリは1つずつ選んで強調する。

- **1ページに全部を縦に並べる（第1版）**: 何がどこにあるか分からず、日次と週次で構成が変わる。タブで切り口を固定し、単位はツールバーで替える。
- **単位もタブにする（日次／週次／月次タブ＋切り口タブの2段）**: タブが2段になり、Manage Asset の1段のタブと揃わない。単位はプルダウン。
- **日付入力欄（`<input type="date">`）だけ**: どの日に日報があるか分からない。Safari では `type="month"`・`type="week"` が使えない。カレンダーのポップオーバーにする。
- **5色以上のカテゴリ**: 帯の上で隣り合う色を見分けられない（§5.2）。
- **選択中以外の日の彩度を落とす（第1版）**: 色が倍に見える。強調は枠線で行う。
- **画面からの日報の削除**: 削除API（`DELETE /api/daily-reports/:date`）は service token 専用で、ブラウザ用の削除経路と削除ボタンは作らない。消すのは送信側の誤り（日付の間違い・送るべきでなかった日報）を直すときだけなので、auto-daily-report の `sync_dashboard.py --delete YYMMDD` で消す（`daily-report-ingest-design.md` §5.3）。
